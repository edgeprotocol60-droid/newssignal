Dashboard, COT, AI Prediction, news, currency strength, interpretation and existing DXY fallbacks remain available. The amber/slate navigation wraps to fit 380px phones.

## Review URLs and checklist

Use the deploy-preview origin supplied by Netlify as `BASE`. This run did not publish to production or obtain a new preview URL. Branch switching is disabled in this environment; the platform handles the review changes and preview. The existing production address is https://tervaxis.netlify.app; review the preview first.

1. Open `BASE/`, sign in normally, and set a 380px viewport. Check Dashboard, COT, AI Prediction and Analysis switch independently. Verify the existing calendar, headlines, news bias, currency strength, interpretation, quotes and chart timeframes still work.
2. Dashboard: each signal row has a grade and score. Signal Detail begins with CONFIRMED LONG, CONFIRMED SHORT or STAND ASIDE and up to three reasons. Neutral/missing checks earn no points. A/B confirmation requires at least 80% data coverage, score ≥65 and no veto; C is observation only.
3. Analysis → 01: select each of the seven markets. Inspect every pass/fail/neutral reason. Technical/news disagreement appears in the news check. Raise minimum R:R above the current setup in section 07 and confirm a veto appears. A relevant high-impact event within 30 minutes also vetoes; an unavailable live calendar blocks confirmation.
4. Analysis → 02: inspect session/daily/weekly and event/day-extreme anchors, standard-deviation bands and ATR/% distances. FX/DXY are time weighted. Choose “Set custom anchor”, tap a candle in Dashboard, and enable VWAP. Return to Analysis to inspect the custom value. Reload after a successful database save to check persistence.
5. Analysis → 03: inspect the ladder, nearest support/resistance, merged labels, rank and tested-bar count. Enable LEVELS on Dashboard. Optional notifications require an explicit browser permission click. Zone alerts are observed-price events, not simulated demonstrations; waiting for a genuine touch may take time.
6. Analysis → 04: inspect relevant driver effects, all driver observations, source availability/latency and both correlation matrices. Missing aligned histories display n/a. A warning marks an absolute 20d/60d correlation difference greater than 0.5.
7. Analysis → 05: inspect all five timeframes, ADX/+DI/−DI, averages, Supertrend, ATR percentile, squeeze and structure events with SAST timestamps. Change fractal wings from 1–5. Enable STRUCTURE on Dashboard. BOS/CHoCH and squeeze-fire alerts require a new observed event; historical events do not all toast on initial load.
8. Analysis → 06: on XAUUSD/NAS100, inspect funding, context, book and trade stream status separately. OI deltas stay n/a until 5m, 1h or 24h observation windows exist. CVD has an observed start time and resets on session changes or socket gaps. For FX/DXY, check the CFTC date and explicit centralised-volume limitation.
9. Analysis → 07: enter account/risk, entry/stop/target and broker contract settings. Check USD and ZAR conversion, ATR stop buttons, lots, R:R, breakeven rate and EV from your own assumed win rate. Set a daily loss limit, record closed trades in R, and export CSV. Confirm “Saved to private Netlify desk” and reload. A storage error is a failed save, not a success; the initial database migration must deploy first.
10. Open `BASE/api/drivers`, `BASE/api/source-health`, `BASE/api/fred?id=DFII10`, `BASE/api/market?sym=%5ETNX&range=6mo&interval=1d`, and `BASE/api/flow?coin=xyz%3AGOLD`. Inspect source labels, timestamps, partial-failure diagnostics and latency. Existing `BASE/api/health` retains news-feed diagnostics. Invalid symbols/series/coins should return 400.
11. In browser DevTools → Network → WS, find one `wss://api.hyperliquid.xyz/ws` connection with 18 subscriptions: six candle timeframes and three flow streams for each HIP-3 market. Look for candle, trades, l2Book, activeAssetCtx and ping/pong messages. Hide the page: the socket closes and periodic REST/computation pauses. Return: it reconnects and refreshes. Disconnect the network to check stale dots and stand-aside behavior.
12. Watch each panel's source dot and “updated Ns ago”. Green denotes a fresh socket observation; amber denotes delayed/daily data; red denotes missing/stale data. Daily and weekly candle panels intentionally use longer freshness thresholds. Timestamp age refers to the source observation, except driver-batch health, which reports the last batch check. Run `runSelfTests()` in the console: all five known-vector checks must pass and the function returns `true`.

## Optional keys

No new API key is required. Hyperliquid, Yahoo, CFTC and FRED use their public endpoints. The existing optional fallback variables remain supported:

- `TWELVE_DATA_API_KEY`: create a free Basic account at https://twelvedata.com/, sign in and copy the key from the API Keys area of your account dashboard. This enables the existing FX time-series fallback when Yahoo fails; it does not replace every driver feed. Free-plan rate limits still apply.
- `ALPHA_VANTAGE_API_KEY`: request a free key at https://www.alphavantage.co/support/#api-key and copy the issued key. This enables the existing optional news/sentiment source. Its result/backoff is durably cached for two hours to reduce quota use.

For either key, open Netlify → this project → Project configuration → Environment variables → Add a variable. Enter the exact name above and paste the value into its private value field. Include the Functions/runtime scope and the deploy-preview context if configuring scopes/contexts; redeploy the preview afterward. Never put a key in HTML, JavaScript, this document or a public repository. No FINNHUB variable is consumed by this implementation. Database credentials are platform-managed and need no manual browser configuration.

## Limits and deviations

- The journal, broker settings and custom anchors persist in a private Netlify Database desk identified by a secure browser cookie. Requested localStorage persistence was not implemented. The desk is browser-specific, not linked to the pre-existing login; clearing its cookie loses access to that desk. The journal is capped at 500 entries. Concurrent tabs can overwrite changes because saves replace the desk document. Export CSV for a portable copy.
- Database durability awaits the deploy-time migration. The local endpoint correctly reported storage unavailable before that migration; no successful production/preview database write is claimed.
- Yahoo data is indicative/delayed, FRED is daily, COT is weekly, and spot FX lacks centralised trade volume. FX/DXY VWAP uses equal candle weights. These feeds cannot honestly be labelled tick-live. FRED observations can be several days old around holidays.
- New/short HIP-3 histories may not support 60 weekly observations or 200-period averages. Such cells stay n/a. Up to 700 bars per series are retained. VWAP anchors older than available intraday history stay n/a. Previous-period levels require full available coverage; exact FX rollover levels use intraday observations, and a full previous FX month will commonly be unavailable in the capped hourly window. Current bars are provisional.
- Session hours use the requested fixed UTC windows, displayed in SAST; they do not follow London/New York daylight-saving changes. Weekly FX anchors use Sunday 22:00 UTC. Chart VWAP curves are sampled from 15m analysis candles; current anchor and band values are also shown as horizontal guides. The chart's price scale is preserved, so out-of-range overlay levels are omitted.
- CVD only covers trades observed in the current connection/session, not a reconstructed historical tape. Funding is hourly and simple annualisation is descriptive. OI deltas need actual elapsed collection time. Streams/alerts over a full 24 hours, real browser notification delivery on the owner's phone, and provider throttling over days were not verified.
- Correlations use matched calendar dates of available closes, not synchronised cross-exchange closing instants. Driver relationships, level merging, crowding thresholds and trend scores are transparent heuristics, not probabilities or forecasts. Level touches count bars rather than independent visits. Round zones count as opposing levels and can conservatively block a setup.
- Analysis REST history refreshes every two minutes, drivers at least every five minutes, long histories every 30 minutes and funding history hourly. Healthy Hyperliquid sockets suppress redundant quote REST polling; outage fallback is limited to every 30 seconds. With the existing quote/news/calendar/signal polls, the normal successful-source request budget is approximately 30,000–35,000 function requests/day for a continuously visible tab, before CDN cache savings. Actual browser fallback retries, manual refreshes or outages can exceed that estimate; no daily production measurement was performed. Free plan usage is not unlimited.
- All drivers were reachable during this run; no Netlify-IP blocking was observed here. Yahoo uses its alternate host, and the existing FX/DXY fallback chain remains intact. There is no separate provider fallback for every driver: a deployment-region block can leave that driver n/a and reduce confirmation coverage. Existing news/calendar availability and fallback warnings remain meaningful.
- No production deployment, new preview URL or manually created review branch is claimed. Review branch/deploy creation belongs to the hosting workflow in this environment.
